# 00-context — Project Identity & Constraints

Owner-approved product context. Drafted by BA, ratified by PM, approved by owner.

| File | Content |
|---|---|
| `project-brief.md` | Product one-paragraph definition, problem, desired outcome, open questions |
| `scope.md` | In-scope / out-of-scope lists; scope-change rule (OD-18) |
| `stakeholders.md` | Roles + **RACI/decision authority** (who can decide what — the KB authority check reads this) |
| `success-metrics.md` | Metric | definition | target | source | status (no targets until owner records them) |
| `glossary.md` | Domain terms; preferred words; vague-word list requiring measures |
| `business-rules.md` | Cross-cutting rules (atomic rules live in `../knowledge/capabilities/`) |
| `constraints.md` | Project constraints incl. data policy (mirrors `project.yaml`), platform, budget, timing |
| `raid.md` | Risks, Assumptions, Issues, Dependencies with owners and review cadence |

Stakeholders table format:

| Stakeholder | Role | Interests | Can decide |
|---|---|---|---|
| Owner | final authority | everything | scope, commitments, material change, deploy, risk acceptance |
| <role> | | | <subject areas per RACI> |
